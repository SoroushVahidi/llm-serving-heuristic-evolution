# LLM Heuristic DSL

The heuristic DSL is a restricted JSON format for deterministic, safe scheduling heuristics that can be generated by a language model and verified before deployment.

## Design Principles

- **No eval / exec / imports** — all computation uses a safe expression tree evaluator.
- **No future information** — variables reference only what is observable at scheduling time.
- **No actual_output_tokens** — the hidden ground-truth field is explicitly forbidden.
- **No randomness at runtime** — tie-breaking is deterministic by design.
- **Simulator objective is the fitness oracle** — weighted_goodput is the signal; the selector is the adaptive baseline heuristics must beat.

## Document Structure

```json
{
  "name": "my_heuristic",
  "description": "Optional human-readable description",
  "tie_breaker": "earliest_deadline",
  "regimes": [
    {
      "condition": {"op": "sub", "args": [{"var": "sys.queue_length"}, {"const": 20.0}]},
      "request_score": {"var": "req.deadline_urgency"}
    }
  ],
  "default": {
    "request_score": {
      "op": "weighted_sum",
      "terms": [
        [{"var": "req.deadline_urgency"}, 0.7],
        [{"op": "div_safe", "args": [{"const": 1.0}, {"var": "req.estimated_kv_cost"}]}, 0.3]
      ]
    },
    "batch_score": {"var": "batch.sum_priority_weight"},
    "admission_condition": {"op": "sub", "args": [{"var": "sys.free_sequence_ratio"}, {"const": 0.1}]}
  }
}
```

### Required Top-Level Fields

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Unique identifier |
| `tie_breaker` | string | Deterministic tie-break rule (see below) |
| `default` | object | Default rule block (must have `request_score`) |

### Optional Fields

| Field | Type | Description |
|-------|------|-------------|
| `description` | string | Human-readable explanation |
| `regimes` | list | Ordered list of conditional rule blocks |

## Rule Block

A rule block contains one or more scoring / filtering expressions:

| Field | Required | Description |
|-------|----------|-------------|
| `request_score` | **YES** | Score used to rank candidates (higher = preferred) |
| `batch_score` | no | Score of the current batch build-up (currently informational) |
| `admission_condition` | no | If >0, admit; else skip. Defaults to always admit |

## Regimes

Regimes are evaluated in order; the first one whose `condition` expression evaluates to >0 is used. If none match, `default` applies.

```json
"regimes": [
  {
    "condition": {"op": "sub", "args": [{"var": "sys.kv_utilization"}, {"const": 0.8}]},
    "request_score": {"op": "neg", "args": [{"var": "req.estimated_kv_cost"}]}
  }
]
```

**Limits**: max 3 regimes by default (configurable).

## Expression Nodes

All expressions are JSON objects with one of three shapes:

### Constant
```json
{"const": 3.14}
```
Range: [-1000, 1000]. Must be finite.

### Variable
```json
{"var": "req.deadline_urgency"}
```
See [Allowed Variables](#allowed-variables) below.

### Operation
```json
{"op": "add", "args": [{"const": 1.0}, {"var": "req.priority_weight"}]}
```

### Allowed Operations

| Op | Args | Description |
|----|------|-------------|
| `add` | 2 | Addition |
| `sub` | 2 | Subtraction |
| `mul` | 2 | Multiplication |
| `div_safe` | 2 | Division with ε denominator guard |
| `min` | 2 | Minimum |
| `max` | 2 | Maximum |
| `neg` | 1 | Negation |
| `abs` | 1 | Absolute value |
| `clip` | 3 | `clip(value, lo, hi)` |
| `sqrt_safe` | 1 | `sqrt(max(0, x))` |
| `log1p_safe` | 1 | `log1p(max(0, x))` |
| `weighted_sum` | terms list | `Σ expr_i × weight_i` |
| `if_then_else` | cond/then/else | Conditional (cond > 0 → then, else else) |

## Allowed Variables

### Request Variables (`req.*`)
Variables computed per candidate request at scoring time.

| Variable | Description |
|----------|-------------|
| `req.prompt_tokens` | Number of prompt tokens |
| `req.predicted_output_tokens` | Model's predicted output length |
| `req.waiting_time` | Time since arrival (now − arrival_time) |
| `req.deadline_slack` | SLO deadline − now |
| `req.deadline_urgency` | 1 / max(slack, 0.001) |
| `req.priority_weight` | Request priority |
| `req.estimated_prefill_cost` | proxy for prefill compute (= prompt_tokens) |
| `req.estimated_decode_cost` | proxy for decode compute (= predicted_output_tokens) |
| `req.estimated_kv_cost` | proxy for KV footprint (= prompt + predicted_output) |

### System Variables (`sys.*`)
Aggregate state of the serving system.

| Variable | Description |
|----------|-------------|
| `sys.queue_length` | Number of requests waiting |
| `sys.active_sequence_count` | Total active sequences across GPUs |
| `sys.kv_utilization` | KV-cache fill fraction |
| `sys.free_sequence_ratio` | Fraction of GPU slots free |
| `sys.token_budget_utilization` | Batch token budget utilisation |
| `sys.arrival_rate_est` | Estimated arrival rate (req/s) |
| `sys.burstiness_cv` | CV of inter-arrival times |
| `sys.recent_slo_violation_rate` | SLO violation rate in recent completions |
| `sys.slo_pressure` | Fraction of queue with slack < 1s |

### Batch Variables (`batch.*`)
State of the batch being built this step.

| Variable | Description |
|----------|-------------|
| `batch.size` | Requests admitted so far this step |
| `batch.sum_prompt_tokens` | Sum of admitted prompt tokens |
| `batch.sum_predicted_output_tokens` | Sum of admitted output tokens |
| `batch.mean_predicted_output_tokens` | Mean predicted output length |
| `batch.max_predicted_output_tokens` | Max predicted output length |
| `batch.length_imbalance` | (max-min)/max output token imbalance |
| `batch.sum_priority_weight` | Sum of priorities in batch |
| `batch.min_deadline_slack` | Minimum deadline slack in batch |
| `batch.deadline_risk` | Fraction of batch with slack < 1s |
| `batch.estimated_kv_cost` | Total estimated KV cost of batch |
| `batch.sum_request_score` | Sum of individual request scores in batch |

## Forbidden Variables

Any variable containing these substrings is rejected:
- `actual_output`
- `future_`
- `oracle_`
- `ground_truth`
- `hidden_`
- `completion_time`

## Allowed Tie-Breakers

| Token | Meaning |
|-------|---------|
| `earliest_deadline` | Lower `slo_deadline` wins |
| `highest_priority` | Higher `priority` wins |
| `shortest_output` | Lower `predicted_output_tokens` wins |
| `shortest_prompt` | Lower `prompt_tokens` wins |
| `arrival_order` | Lower `arrival_time` wins |
| `lowest_request_id` | Lower `request_id` wins |
| `lowest_kv_cost` | Lower `prompt_tokens` wins |

## Default Limits

| Parameter | Default |
|-----------|---------|
| `max_batch_candidates` | 64 |
| `max_regimes` | 3 |
| `max_expression_depth` | 6 |
| `max_terms` | 16 |
| `max_nodes` | 64 |
| `max_constant` | 1000.0 |
| `min_constant` | −1000.0 |

## Usage

### Verify a heuristic file
```bash
python scripts/verify_heuristic_dsl.py configs/heuristics/examples/edf_like.json
python scripts/verify_heuristic_dsl.py configs/heuristics/examples/*.json --strict
```

### Run smoke comparison against FIFO
```bash
python scripts/run_heuristic_policy_smoke.py
python scripts/run_heuristic_policy_smoke.py --arrival-rate 25 --duration 30
```

### Programmatic use
```python
from llmserveopt.heuristics import build_heuristic_policy, verify_heuristic
import json

with open("my_heuristic.json") as f:
    doc = json.load(f)

result = verify_heuristic(doc)
if not result.valid:
    for code, msg in result.errors:
        print(f"  [{code}] {msg}")
else:
    policy = build_heuristic_policy(doc)
    # use policy in simulator: run_policy(policy, requests, gpu_configs)
```

## Package Structure

```

├── __init__.py          — public API exports
├── dsl_schema.py        — ALLOWED_VARS, FORBIDDEN_*, ALLOWED_OPS, DEFAULT_LIMITS
├── expressions.py       — safe recursive expression evaluator (no eval/exec)
├── verifier.py          — VerificationResult + verify_heuristic()
├── compiler.py          — CompiledHeuristic + compile_heuristic()
├── policy.py            — HeuristicPolicy(BasePolicy) + build_heuristic_policy()
└── examples.py          — programmatic example constructors
```

## Fitness Oracle

The fitness signal is always **weighted_goodput**:

```
weighted_goodput = Σ(priority_i × 1[met_SLO_i]) / Σ(priority_i)
```

Tie-breaks in order: lower SLO violation rate → lower p95 TTFT → lower p95 latency → higher throughput.

**The selector is the adaptive baseline**, not the oracle. An LLM-generated heuristic must beat the selector (or best fixed policy) on held-out workload windows to be considered useful.
