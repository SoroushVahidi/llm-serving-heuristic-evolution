# Dataset and Workload Planning

**Branch:** phase2b5-external-baselines  
**Date:** 2026-06-25  
**Phase:** 2B.5 — External Baseline Coverage

This document classifies every workload type relevant to the external baseline comparison.
No data is downloaded and no full experiments are run in this phase.

---

## 1. BurstGPT Natural Trace

| Field | Value |
|---|---|
| **Purpose** | Calibrated realistic baseline; closest to real production traffic |
| **Baselines stressed** | FIFO, EDF, LLF (deadline urgency), Orca-style, vLLM-style |
| **Supports TTFT / TPOT / SLO-goodput** | Yes (all metrics supported once TTFT is modelled) |
| **Likely cost / runtime** | Low-to-medium (< 5 min wall clock for 20-policy sweep at 500 requests) |
| **Data exists in repo** | Yes — `data/burstgpt/` (loaded via `workloads/burstgpt.py`) |
| **Next action** | Use as primary comparison workload for Phase 2B.5 evaluation |

## 2. BurstGPT Scaled / Overload Traces

## 7. Prediction-Noise Variants

| Field | Value |
|---|---|
| **Purpose** | Sensitivity analysis: how much do policies degrade when `predicted_output_tokens` is noisy? Critical for LLF, ESTF, SOF |
| **Baselines stressed** | LLF (laxity estimate breaks), ESTF (service estimate breaks), SOF, multi-bin batching |
| **Supports TTFT / TPOT / SLO-goodput** | Yes |
| **Likely cost / runtime** | Medium (run each policy at 2-3 noise levels: 0%, 35%, 70%) |
| **Data exists in repo** | Yes — `burstgpt_moderate_noise035/`, `burstgpt_moderate_noise070/` results exist |
| **Next action** | Include LLF and ESTF in existing noise-variant sweeps; no new data generation needed |

## 8. Forced-Full-Admission Overload Regime

| Field | Value |
|---|---|
| **Purpose** | Compare selective-admission (normal mode) vs. forced-full-admission (all requests must be served); isolates admission-control effect |
| **Baselines stressed** | All policies (forced-full-admission removes the safety valve) |
| **Supports TTFT / TPOT / SLO-goodput** | Yes — `completion_fraction` metric is critical here |
| **Likely cost / runtime** | Medium (doubles the number of runs) |
| **Data exists in repo** | Partial — `phase2a4_2b4_final_eval/` has both selective and forced runs |
| **Next action** | Use `completion_fraction` metric (now added to `RunMetrics`) to clearly distinguish selective vs. forced-admission results; add to report headers |

## Cost / Runtime Estimates

All estimates for a 20-policy sweep, 500 requests, single GPU, single seed:

| Workload | Est. wall-clock |
|---|---|
| BurstGPT natural (1 seed) | ~1-2 min |
| BurstGPT scaled (1 seed) | ~1-2 min |
| Mixed-SLO (1 seed) | <1 min |
| Prefill-heavy (1 seed) | ~1-2 min |
| Noise variants × 3 levels | ~3-6 min |
| Full sweep (5 workloads, 3 seeds, 20 policies) | ~15-30 min |

All estimates are CPU-only (no GPU required for simulator). No paid API calls needed.
