## 7. Uncertainty, OOD, And Fallback

* **Model selected**: `gradient_boosting`, not an ensemble type this
  pipeline's uncertainty estimator supports (`_predict_with_uncertainty`
  only computes per-tree variance for `RandomForestRegressor`) --
  `uncertainty_method: "unsupported_for_selected_model_type"` is recorded
  explicitly rather than silently reporting a meaningless 0.0, exactly as
  designed and as happened (for a different reason -- KNN then, GBM now)
  in the first attempt. This remains a real, documented limitation (§9).
* **OOD method**: max-abs z-score vs. the 30-window dev causal-feature
  distribution, clipped at 50.0 (the CC5-report bugfix from the first
  attempt), threshold 2.0.
* **Abstention/fallback rate**: **36.8% (28/76)**, down from 67% in the
  first attempt -- a direct, expected consequence of the larger (30 vs 6)
  development set giving the OOD gate a much less minuscule
  "in-distribution" region. All 28 abstentions were OOD-triggered (none
  uncertainty-triggered, consistent with the non-ensemble model).
  Fallback policy: `fixed__estimated_service_time_first` (the dev-fit best
  fixed policy).
* Per-regime abstention is highly uneven: `underloaded`, `azure_conversation_like`,
  and `burstgpt_derived` abstain 100% of the time (all real-trace or the
  most extreme-intensity synthetic OOD variant); `kv_pressure`,
  `mixed_slo`, `priority_conflict`, and `saturated` never abstain (0%).
  This is a legible, structurally sensible pattern -- the gate is
  correctly identifying which regimes are genuinely furthest from the
  training distribution, not behaving arbitrarily.

## 8. Decision Gate Application

CC5's existing, unmodified `determine_dataset_verdict`-equivalent logic
(`determine_cc5_verdict` in `cc5_contextual_predictor.py`) was applied
without any threshold or branch changes:

* `completion_violations == 0` -> does not trigger `STOP_OR_REDESIGN`.
* `n_eval = 76 >= 8` -> skips the small-sample `INCONCLUSIVE` branch used
  at n=6.
* `beats_fixed = predictor_mean (0.4006) >= best_fixed_mean (0.3895)` ->
  **True**.
* `beats_global = predictor_mean (0.4006) >= best_global_mean (0.4025)` ->
  **False** (predictor is 0.0019 below global composition -- within noise,
  but the gate is a strict `>=` comparison of point estimates, applied
  exactly as written, not loosened for this report).
* `competitive_with_selector = predictor_mean >= hard_selector_mean - 0.01`
  -> `0.4006 >= 0.3838` -> **True**.
* Since `beats_fixed and beats_global and competitive_with_selector` is
  `False` (because `beats_global` is `False`), the verdict falls to the
  `else` branch: **`REGIME_SPECIFIC_ONLY`**, `"predictor shows value on
  some but not all comparisons"`.

No manual override or threshold adjustment was applied to reach this
verdict; it is the direct, mechanical output of the pre-existing gate
function given the actual held-out numbers.

## 9. Limitations

* **The decisive predictor-vs-global-composition gap (0.0019 ANWG) is well
  within the bootstrap CI overlap** -- `REGIME_SPECIFIC_ONLY` here reflects
  a strict point-estimate inequality, not a confidently-resolved "global
  composition is better." A larger or differently-sampled held-out set
  could plausibly flip this specific comparison; the roadmap's "Current
  Scientific Interpretation" section's three-outcome framing should be
  read as "outcome 1 (predictor wins) and outcome 2 (global composition
  wins) are both still live, with the current data leaning marginally
  toward outcome 2's premise (global composition is very strong) while
  simultaneously supporting outcome 1's implication that the predictor
  clearly adds value over naive fixed-policy selection."
* **`uncertainty_method` remains unsupported for the selected model type**
  (gradient_boosting this run, KNN last run) -- across two independent
  retrains, LOWO-CV has never selected the one model family
  (`RandomForestRegressor`) this pipeline's ensemble-disagreement
  uncertainty estimator supports. This is now a load-bearing limitation
  worth addressing directly (not merely documenting) before a third
  attempt: either extend `_predict_with_uncertainty` to support
  gradient-boosting/KNN-neighbor-spread uncertainty, or add ensemble
  uncertainty as a factor in model selection itself, so the deployed model
  always has a working, non-trivial uncertainty signal rather than
  OOD-only gating.
* **Direct parameter regression remains untrained** (same identifiability
  argument as the first attempt, now revisited with more data: of 76
  held-out windows, `weighted_primitive_mixture` is the oracle winner on
  30 -- enough positive examples in principle to reconsider this target in
  a future iteration, though the *training*-side count is what matters
  for fitting, and that split (30 dev windows) still yields relatively few
  `weighted_primitive_mixture`-labeled dev examples specifically).
* **Real-trace window diversity is still limited** to request-transform
  intensity variants of the same 2 underlying trace files (Azure, BurstGPT)
  rather than independent trace slices, per CC1's shared trace-loading
  infrastructure only ever taking a prefix of a trace (documented in the
  original CC4 report, unchanged here).

CC5 does not yet fully pass (verdict `REGIME_SPECIFIC_ONLY`, not
`PROCEED`), so **CC6 is not queued**. CC5 remains `IN PROGRESS`. The
single most informative next step, in priority order:

1. **Address the uncertainty-method gap (§9)** before any further data
   expansion -- across two retrains, no run has produced a model type this

2. If (1) does not change the predictor-vs-global-composition outcome,
   the next lever is **regime-specific analysis**: `REGIME_SPECIFIC_ONLY`
   is exactly the verdict this decision gate names for "some regimes
   benefit, not universally" -- a per-regime breakdown of predictor regret
   vs. global-composition regret (both already computable from
   `per_window_predictions.csv` and `regret_tables.csv`) would show
   whether the predictor's value is concentrated in specific regimes
   (supporting a regime-gated deployment rather than a universal one)
   before considering further dataset expansion or model redesign.
3. Do not begin CC6 dynamic adaptation, evolutionary/QD library expansion,
   or LLM-guided synthesis work until either (1)+(2) resolve the
   predictor-vs-global-composition question with a clear winner, or a
   further-expanded held-out set (see CCD-016's original >=50 target,
   already exceeded at 76 -- a next iteration might target closing the
   gap's confidence interval specifically, e.g. via targeted additional
   sampling in the `long_output`/`burstgpt_derived`/`azure_conversation_like`
   regimes that dominate the abstention rate) makes the comparison
   unambiguous.
