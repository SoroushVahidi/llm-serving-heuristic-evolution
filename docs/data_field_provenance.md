# Data Field Provenance

## Field Sources

| Field | BurstGPT | ShareGPT | Simulator use |
|---|---|---|---|
| `arrival_time` | real (normalized from unix timestamp) | synthetic (generated by arrival model) | online-visible |
| `prompt_tokens` | real (from `Request Token` column) | derived by tokenizer | online-visible |
| `actual_output_tokens` | real (from `Response Token` column) | derived by tokenizer | simulator-only (hidden from policies) |
| `predicted_output_tokens` | synthetic (lognormal noise on actual) | synthetic (lognormal noise on actual) | online-visible |
| `class_id` | synthetic (sampled from weight distribution) | synthetic (sampled from weight distribution) | online-visible |
| `priority` | synthetic (derived from class_id) | synthetic (derived from class_id) | online-visible |
| `slo_deadline` | synthetic (arrival_time + slo_slack per class) | synthetic (arrival_time + slo_slack per class) | online-visible |

## Key Distinction

**Online-visible**: The field is exposed to scheduling policies at decision time.
Policies may use it in their scheduling logic.

**Simulator-only (hidden)**: The field is used by the simulator to compute
ground-truth metrics but is **not** visible to scheduling policies. This
simulates the information asymmetry in real serving: the system does not know
how many tokens a request will actually generate until it finishes.

## Synthetic Field Details

### `predicted_output_tokens` (BurstGPT and ShareGPT)
Generated by applying multiplicative lognormal noise to `actual_output_tokens`:
```
predicted = round(actual * exp(Normal(bias, sigma)))
```
Default: `sigma=0.35`, `bias=0.0`. See `configs/traces/` for variants.

The prediction noise mode can be changed to study how prediction accuracy
affects policy performance:
- `exact`: perfect prediction (oracle baseline)
- `lognormal`: symmetric noise (default)
- `biased_under`: systematic underprediction
- `biased_over`: systematic overprediction
- `bucket`: coarse bucketing into [32, 128, 512, 2048, 4096]

### `class_id`, `priority`, `slo_deadline` (both datasets)
Assigned independently of actual request content using configurable weights:

| Class | Default weight | Default priority | Default SLO slack |
|---|---|---|---|
| interactive | 50% | 3.0 | 2.0 s |
| standard | 35% | 2.0 | 6.0 s |
| batch | 15% | 1.0 | 20.0 s |

These are **not derived from** the request content. A 5-token request is
equally likely to be "interactive" as a 5000-token request.

## Safe Claim Examples

**Safe**: "Under this augmentation configuration, EDF achieves lower SLO
violation rates than FIFO on BurstGPT arrival patterns."

**Safe**: "The BurstGPT token distribution has heavier tails than the
synthetic lognormal distribution used in the baseline comparison."

## Unsafe Claim Examples

**Unsafe**: "EDF achieves X% lower SLO violation rates in production BurstGPT
deployments." (SLO deadlines are synthetic, not from BurstGPT.)

**Unsafe**: "The simulator results generalize to production LLM serving." (The
simulator has many simplifications: single GPU, no preemption, etc.)

**Unsafe**: "BurstGPT arrival patterns are representative of all production LLM
workloads." (BurstGPT is from specific deployments at a specific time.)

## Trace Metadata

Extended JSONL traces include a `metadata.synthetic_fields` list indicating
which fields were synthetically generated:
```json
{
  "request_id": 0,
  "arrival_time": 0.0,
  ...
  "source": "burstgpt",
  "metadata": {
    "synthetic_fields": ["predicted_output_tokens", "class_id", "priority", "slo_deadline"]
  }
}
```
